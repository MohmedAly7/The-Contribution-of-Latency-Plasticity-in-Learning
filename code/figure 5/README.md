# Figure 5 — Effect of Background Spikes on Timing

> **Fig. 5: Effect of background spikes on timing.**
> **a,** The timing diagram for neuron $n_4$ illustrates that its firing period is shortened by temporally clustered excitatory inputs, which summate to reach the spike threshold. Short arrows indicate inputs from inactive neurons (firing stochastically), whereas long arrows denote inputs from active neurons.
> **b,** Temporal jitter resulting from an extraneous spike is negligible. If the spike occurs early in the firing period, its impact decays over time due to membrane leakage. Should it arrive within the window of aligned input events, it merely replaces the last arrived event; this substitution has no meaningful effect, given the exceedingly brief duration of the arrival window.

---

## Overview

This folder contains the code that produces both panels of Figure 5.

**Panel a** (`figure 5a.cpp` + `figure5a.m`) uses a large-scale event-driven LIF network simulation (10 neurons, 40 million training events) to demonstrate how temporally clustered synaptic inputs summate and shorten the firing period of neuron $n_1$. The resulting spike raster is visualised in MATLAB.

**Panel b** (`figure5b.m`) is a standalone MATLAB LIF integrator that illustrates why a single extraneous spike produces negligible timing jitter: an early-arriving spike decays before threshold, while a late-arriving spike simply replaces the last aligned input within the brief coincidence window.

> ⚠️ **The C++ simulation (`figure 5a.cpp`) is computationally intensive.** The main training loop runs **40 million events**, recording the final 1,000,000 events (`q > 39000000`). On a modern desktop CPU this typically takes **several minutes to over an hour** depending on clock speed and compiler optimisation level. Plan accordingly before running.

## How to Build and Run

### Requirements
- A C++ compiler supporting C++11 or later (`g++`)
- MATLAB (any recent version)


---

### Panel a — C++ Simulation

#### Compile
```bash
g++ -O2 -o figure5a "figure_5a.cpp"
```

> Using `-O2` or `-O3` is strongly recommended. Optimised builds can be **2–4× faster** than debug builds on a 40-million-event loop.

#### Run
```bash
./figure5a
```

The program prints:
- Initial random firing offsets for each neuron
- Weight/latency tables at the start and end of training
- Progress counters every 2,000,000 events during training and every 200,000 events during the recording pass
- Final simulation time and random seed

**Expected runtime:** several minutes to over an hour depending on hardware. The terminal output provides progress updates so you can monitor the run.

On completion the file `figure5a.neuron` is written to the current directory.

#### Visualise in MATLAB
```matlab
run('figure5a.m')
```

`USE_STATIC = true` by default — no interactive input is needed. The script reads `figure5a.neuron` and renders the spike raster for panel **a**.

---

### Panel b — MATLAB Simulation

No compilation step is required. Simply open MATLAB in this folder and run:

```matlab
run('figure5b.m')
```

The script is fully self-contained: it defines two input current patterns, integrates the LIF equations, and plots both the membrane potential and input current traces in a single figure.

## Model Description

### Panel a — 10-Neuron Event-Driven LIF Network (`figure_5a.cpp`)

#### Network Structure

| Property | Value |
|----------|-------|
| Total neurons | 10 (`cc = 10`) |
| Active neurons (suprathreshold drive) | 5 (`nActive = 5`, indices 0–4) |
| Inactive neurons (subthreshold + noise) | 5 (indices 5–9) |
| Connectivity | All-to-all (excluding self) |



#### LIF Dynamics

Between events the membrane voltage decays as:

$$V(t) = V_{ss} + \bigl(V_0 - V_{ss}\bigr)\,e^{-(t-t_0)/\tau_m}, \qquad V_{ss} = I_{input} \cdot R_M$$

A spike is emitted when $V \geq V_{thr} = 1.0$, after which $V$ resets to 0.

#### Plasticity Rules

**STDP (weight updates)** — applied at every firing event:
$$\Delta\omega = +\eta_w \cdot e^{-\Delta t / T_2} \quad \text{(potentiation, pre before post)}$$
$$\Delta\omega = -\eta_w \cdot e^{-\Delta t / T_2} \quad \text{(depression, post before pre)}$$

**Latency plasticity** — applied at every firing event using a Gaussian-shaped update:
$$\Delta L = \eta_L \cdot \Delta t \cdot \frac{e^{-\Delta t^2 / T_D^2}}{T_D}$$

Latencies are clipped to $[0.01,\, 80.01]$ ms to prevent unphysical values.

#### Key Parameters

| Parameter | Symbol | Value | Description |
|-----------|--------|-------|-------------|
| Firing threshold | $V_{thr}$ | 1.0 | Normalised membrane voltage |
| Membrane time constant | $\tau_m$ | 20 ms | RC decay rate |
| Membrane resistance | $R_M$ | 10 MΩ | RC circuit resistance |
| STDP time constant | $T_2$ | 20 ms | Weight update window |
| Latency plasticity time constant | $T_D$ | 5 ms | Latency update window |
| Weight learning rate | $\eta_w$ | `1×10⁻⁴` | |
| Latency learning rate | $\eta_L$ | `1×10⁻²` | |
| Maximum weight | $\omega_{max}$ | 0.051 | Hard clip |
| Latency range | $L$ | [0.01, 80.01] ms | Hard clip |
| Active neuron input current | $I_a$ | `(1.1 + rand×0.12) / R_M` | Suprathreshold |
| Inactive neuron input current | $I_i$ | `1.02 / R_M` | Near-threshold |
| Refractory offset | — | 0.15 ms | Added to computed fire time |
| Random seed | — | `1761044228` | Fixed for reproducibility |

### Panel b — Standalone LIF Integrator (`figure5b.m`)

`figure5b.m` integrates a single-compartment LIF neuron under two different input current patterns using the forward-Euler method, demonstrating the effect of extraneous spike timing on membrane potential.

#### Neuron Parameters

| Parameter | Symbol | Value |
|-----------|--------|-------|
| Membrane capacitance | $C_m$ | 200 pF |
| Membrane resistance | $R_m$ | 100 MΩ |
| Resting potential | $V_{rest}$ | −70 mV |
| Spike threshold | $V_{th}$ | −55 mV |
| Reset potential | $V_{reset}$ | −75 mV |
| Membrane time constant | $\tau_m = R_m C_m$ | 20 ms |
| Simulation duration | — | 20 ms |
| Time step | $dt$ | 0.01 ms |

#### Input Patterns

| Pattern | Colour | Description |
|---------|--------|-------------|
| Regular pulses | Orange (solid) | 6 pulses: one continuous background current (150 pA) + 5 aligned high-amplitude inputs (1550 pA) at 15–16 ms |
| Extraneous pulses | Blue (dotted) | 7 pulses: same as above but with one additional early-arriving extraneous spike (1550 pA) at 7 ms |

## Output File Format (`figure5a.neuron`)

### Header (4 bytes)

| Bytes | Type | Value |
|-------|------|-------|
| 0–3 | `int32` | Number of neurons `cc` = 10 |

### Data records (24 bytes each)

Written by `save(i, j)` for every event in the recording phase.

| Bytes | Type | Field | Notes |
|-------|------|-------|-------|
| 0–7 | `double` | Simulation time `t` (ms) | Absolute timestamp |
| 8–11 | `int32` | Pre-synaptic neuron index `i` (0-based) | |
| 12–15 | `int32` | Post-synaptic neuron index `j` (0-based) | |
| 16–23 | `double` | Amplitude value | `1.5` for a firing event (`i == j`); `−(w[j][i] / maxW × 0.5) − 0.5` for a synaptic reception |

## Visualisation Details

### Panel a (`figure5a.m`)
- One subplot per selected neuron rendered as a stem plot; x-axes are linked.
- Firing events (`i == j`, amplitude = 1.5) and synaptic inputs (amplitude < 0) are plotted in the colour of their source neuron.
- Firign period values are annotated as text between consecutive spikes when Firing period mode is active (negative `numberOfEventPage`).
- `USE_STATIC = true` by default; all parameters (file, neurons, page) are hardcoded at the top of the script.

### Panel b (`figure5b.m`)
- Two-panel figure: membrane potential (top) and input current (bottom), x-axes linked.
- Threshold and resting potential reference lines are drawn on the voltage panel.
- Orange solid line = Regular Pulses; Blue dotted line = Extraneous Pulses.

## Reproducing Figure 5

1. Compile `figure_5a.cpp` with optimisation (`-O2`) and run it. **Allow significant time for the 40-million-event training phase.**
2. Once `figure5a.neuron` is written, open MATLAB in the same directory and run `figure5a.m` for panel **a**.
3. Run `figure5b.m` independently for panel **b** — no C++ step is required.
